# Qubool Supabase backend

## Local development

Install a current Supabase CLI and Docker, copy `supabase/.env.example` to the repository `.env` (do not commit it), then run `supabase start` and `supabase db reset`. The reset applies timestamped migrations in order and seeds only immutable/reference data. Start functions with `supabase functions serve`.

## Architecture

`auth.users` owns identity; `profiles.id` is the same UUID and is created by a protected Auth trigger. Lookup data is normalized. Pair records use canonical low/high IDs, preventing duplicate matches. Conversations are one-to-one with matches. Messages use `(conversation_id, created_at DESC, id DESC)` keyset pagination; pass the final cursor to subsequent requests. Profile discovery has partial, trigram, and full-text indexes. Audit and rate-limit data is append-only; retain/partition it with an operational migration once volume warrants it.

The authoritative migrations are deliberately incremental. Never edit a migration already deployed: generate the next timestamped migration, test `supabase db reset`, then use `supabase db push` in CI/production. Backups, point-in-time recovery, and index monitoring must be enabled in the hosted project.

## Security model

RLS and `FORCE ROW LEVEL SECURITY` are enabled on every application table. JWT `app_metadata.role` controls moderator/admin access; only the server-side service-role workflow may assign it. Client code must never receive `SUPABASE_SERVICE_ROLE_KEY`. All RPC functions have bounded arguments and server-side rate limits; route user writes through the RPCs where business invariants matter. Profiles use soft deletion (`deleted_at`). App audit events should be written from trusted Edge Functions/service contexts.

Storage paths are UUID-owned: `profile-images/<user-id>/<asset-id>.<ext>`, `verification-documents/<user-id>/<asset-id>.<ext>`, and `chat-media/<user-id>/<asset-id>.<ext>`. The first is public by product requirement; the others are private and checked by RLS. Use private signed URLs for chat media rather than exposing bucket URLs.

Realtime publication includes `messages`, `notifications`, and `interests`. For typing and presence, use a client-side Realtime channel named `conversation:<conversation-id>` after first verifying conversation membership through the database; never treat presence payloads as authorization.

## Auth and OAuth

Email/password requires verified email, strong passwords, and secure password-change confirmation. Magic links use Supabase email OTP and inherit the configured redirect allowlist. Password-reset links are generated by Supabase Auth and must return to `/auth/callback`.

For Google Cloud Console: create an OAuth 2.0 **Web application**, add `http://localhost:54321/auth/v1/callback` for local development and `https://<project-ref>.supabase.co/auth/v1/callback` in production under Authorized redirect URIs. Put the client ID/secret in local `.env` and Hosted Project Authentication > Providers in production. Add your app URLs (for example `https://app.qubool.example/auth/callback`) under Auth URL Configuration, not the Google callback URL.

For Apple: create a Services ID, configure the same Supabase callback in Apple Developer, generate/sign the client secret, and set its client ID/secret in the Auth Provider settings. Apple credentials rotate; record an owner and rotation date.

## Edge Functions and deployment

Each function verifies the caller’s JWT except `webhooks`, which validates Stripe’s signed payload. Required production secrets: `ALLOWED_ORIGINS`, `RESEND_API_KEY`, `EMAIL_FROM`, `STRIPE_SECRET_KEY`, and `STRIPE_WEBHOOK_SECRET`. Set them with `supabase secrets set`; do not use `.env` as a deployment secret store. Deploy explicitly: `supabase functions deploy send-email send-notification image-processing profile-verification moderation webhooks`.

Before production deploy, link the project, configure Auth providers/SMTP/custom domains in the Dashboard, set redirect URLs, run `supabase db push`, deploy functions, seed buckets if needed, and inspect Supabase Security and Performance Advisors. Configure an external WAF/rate limiter for unauthenticated endpoints and monitor function/auth/database logs.
